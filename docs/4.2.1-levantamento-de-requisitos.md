# 4.2.1 Levantamento de Requisitos

> 🔒 Esta seção entra na **Aula 23**. Deixe como está até lá. Na aula, o molde chega pelo AVA, e a seção pronta do BiblioTech aparece no repositório do modelo.

## 1. Como os requisitos foram levantados

Os requisitos foram levantados a partir da descrição do projeto apresentada na seção 4.1, considerando o problema, o propósito, o objetivo, os usuários, o escopo e as características principais do sistema.

A análise foi realizada considerando as necessidades de cadastrar, consultar, editar e organizar os pedidos de corte de madeira, além de acompanhar o andamento das entregas.

A confirmação de detalhes específicos sobre as informações de cada pedido e sobre as regras para atualização e conclusão das entregas ainda depende de confirmação com o cliente.

## 2. Da fala do cliente à necessidade

**F1 — Cadastro de pedidos**

Fala do cliente: "Recebemos os pedidos de corte de madeira pelo WhatsApp."

Necessidade identificada: O sistema precisa permitir o cadastro dos pedidos dos clientes de forma organizada.

**F2 — Organização das informações**

Fala do cliente: "As informações ficam espalhadas nas conversas, dificultando encontrar os pedidos."

Necessidade identificada: O sistema precisa centralizar as informações dos pedidos em um único lugar.

**F3 — Acompanhamento dos pedidos**

Fala do cliente: "Às vezes fica difícil saber quais pedidos ainda precisam ser entregues."

Necessidade identificada: O sistema precisa permitir acompanhar o andamento dos pedidos e identificar os que estão pendentes.

**F4 — Atualização dos pedidos**

Fala do cliente: "Precisamos conseguir atualizar as informações dos pedidos e registrar quando forem entregues."

Necessidade identificada: O sistema precisa permitir editar os pedidos e atualizar seu andamento.

## 3. Histórias de usuário

**HU01 — Cadastrar pedido**

Como usuário, quero cadastrar um pedido de corte de madeira, para manter as informações dos clientes organizadas no sistema.

Origem: F1.

**HU02 — Consultar pedidos**

Como usuário, quero consultar os pedidos cadastrados, para encontrar suas informações de forma rápida.

Origem: F1 e F2.

**HU03 — Editar pedido**

Como usuário, quero editar um pedido cadastrado, para manter suas informações atualizadas e corretas.

Origem: F4.

**HU04 — Acompanhar pedidos**

Como usuário, quero acompanhar o andamento dos pedidos, para saber quais ainda estão pendentes e quais já foram entregues.

Origem: F3 e F4.

## 4. Requisitos funcionais

**RF01 — Cadastrar pedido**

O sistema deve permitir cadastrar pedidos de corte de madeira.

Origem: HU01 / F1.

**RF02 — Consultar pedidos**

O sistema deve permitir consultar os pedidos cadastrados.

Origem: HU02 / F1 e F2.

**RF03 — Editar pedido**

O sistema deve permitir editar as informações de um pedido cadastrado.

Origem: HU03 / F4.

**RF04 — Atualizar andamento**

O sistema deve permitir atualizar o andamento de um pedido.

Origem: HU04 / F3 e F4.

**RF05 — Listar pedidos**

O sistema deve listar os pedidos cadastrados
