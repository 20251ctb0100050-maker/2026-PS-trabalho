# 4.2.1 Levantamento de Requisitos

> 🔒 Esta seção entra na **Aula 23**. Deixe como está até lá. Na aula, o molde chega pelo AVA, e a seção pronta do BiblioTech aparece no repositório do modelo.

1. Como os requisitos foram levantados

Os requisitos foram levantados a partir da descrição do projeto apresentada na seção 4.1, considerando o problema, o propósito, o objetivo, o usuário, o escopo e as características principais do sistema.

A análise foi realizada considerando as necessidades de cadastrar, consultar, editar, excluir e organizar informações sobre marcas de carros.

A confirmação de detalhes específicos sobre os dados que devem ser cadastrados e sobre as regras para edição e exclusão ainda depende de confirmação com o cliente. ❓

2. Da fala do cliente à necessidade

F1 — Cadastro e consulta de marcas

Fala do cliente: ❓ Preciso cadastrar as marcas de carros e consultar essas informações de forma rápida.

Necessidade identificada: O sistema precisa permitir o cadastro e a consulta das marcas de carros de forma organizada.

F2 — Organização das informações

Fala do cliente: ❓ Quando os dados ficam espalhados ou são anotados manualmente, fica mais difícil encontrar e atualizar as informações.

Necessidade identificada: O sistema precisa centralizar e organizar as informações das marcas para facilitar a consulta e a atualização.

F3 — Alteração de informações

Fala do cliente: ❓ Quero conseguir alterar uma marca quando alguma informação estiver incorreta.

Necessidade identificada: O sistema precisa permitir a edição dos dados de uma marca cadastrada.

F4 — Exclusão de informações

Fala do cliente: ❓ Quero poder excluir uma marca que não seja mais necessária.

Necessidade identificada: O sistema precisa permitir a exclusão de uma marca cadastrada quando ela não for mais necessária.

3. Histórias de usuário

HU01 — Cadastrar marca

Como usuário, quero cadastrar uma marca de carro, para manter as informações organizadas no sistema.

Origem: F1.

HU02 — Consultar marcas

Como usuário, quero consultar as marcas cadastradas, para encontrar as informações de forma rápida.

Origem: F1 e F2.

HU03 — Editar marca

Como usuário, quero editar uma marca cadastrada, para manter suas informações atualizadas e corretas.

Origem: F2 e F3.

HU04 — Excluir marca

Como usuário, quero excluir uma marca cadastrada, para remover informações que não sejam mais necessárias.

Origem: F4.

4. Requisitos funcionais

RF01 — Cadastrar marca

O sistema deve permitir cadastrar uma marca de carro.

Origem: HU01 / F1.

RF02 — Consultar marcas

O sistema deve permitir consultar as marcas cadastradas.

Origem: HU02 / F1 e F2.

RF03 — Editar marca

O sistema deve permitir editar os dados de uma marca cadastrada.

Origem: HU03 / F2 e F3.

RF04 — Excluir marca

O sistema deve permitir excluir uma marca cadastrada.

Origem: HU04 / F4.

RF05 — Listar marcas

O sistema deve listar as marcas cadastradas de forma organizada.

Origem: Escopo e características principais da seção 4.1.

RF06 — Localizar marca

O sistema deve permitir localizar uma marca entre os registros cadastrados.

Origem: Escopo da seção 4.1.

5. Requisitos não funcionais

RNF01 — Usabilidade

O sistema deve possuir uma interface simples para facilitar o uso pelo usuário.

Categoria: Usabilidade.

Origem: Características principais da seção 4.1.

RNF02 — Organização

O sistema deve manter os dados das marcas organizados para facilitar a consulta e a manutenção das informações.

Categoria: Organização.

Origem: Propósito e características principais da seção 4.1.

RNF03 — Rapidez

O sistema deve permitir que as informações das marcas sejam consultadas de forma rápida.

Categoria: Desempenho.

Origem: Propósito da seção 4.1.

6. Conferência com a seção 4.1

Os requisitos foram conferidos com o que foi definido na seção 4.1.

O cadastro de marcas está representado pelo RF01.
A consulta das marcas está representada pelo RF02.
A edição das informações está representada pelo RF03.
A exclusão das marcas está representada pelo RF04.
A organização e apresentação das informações estão representadas pelo RF05.
A localização de uma marca nos registros está representada pelo RF06.
As histórias de usuário possuem requisitos funcionais relacionados.
Os requisitos não funcionais estão relacionados às características de simplicidade, organização e rapidez definidas na seção 4.1.

O que mudou em relação à seção 4.1: a descrição inicial do projeto foi transformada em requisitos mais específicos para orientar o desenvolvimento do sistema. Também foram detalhadas as ações de cadastro, consulta, edição, exclusão, listagem e localização das marcas.
