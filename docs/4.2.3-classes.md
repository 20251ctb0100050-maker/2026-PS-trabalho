## 1. Identificação de Substantivos (Candidatos a Classes)

A partir da análise dos casos de uso (Aula 24) e do funcionamento real do serviço de corte de madeira realizado por Eduardo, foram identificados os seguintes substantivos:

| Substantivo identificado | Classificação | Justificativa |
|---|---|---|
| **Responsável (Eduardo)** | Classe (`Responsavel`) | Pessoa que gerencia, cadastra e atualiza os pedidos pelo celular. |
| **Cliente** | Classe (`Cliente`) | Pessoa que solicita o serviço de corte de madeira. |
| **Pedido** | Classe (`Pedido`) | Elemento central do sistema que reúne o cliente, a data, o status e o valor total. |
| **Corte / Metragem** | Classe (`ItemCorte`) | Representa a quantidade em metros solicitada, o valor por metro (R$ 35,00) e o subtotal. |
| **Andamento / Pendente** | Enumeração (`StatusPedido`) | Define as etapas do pedido (ex.: Pendente, Em andamento, Concluído). |
| **Sistema / Cadastro** | Descartado | Termos genéricos de software que não representam entidades do negócio. |

## 2. Definição das Classes, Atributos e Operações

O modelo conta com **5 classes** principais que atendem a todos os requisitos levantados:

### 2.1 Classe `Responsavel`
Representa o operador do sistema (Eduardo).
* **Atributos:**
  * `- idResponsavel: int`
  * `- nome: String`
* **Operações:**
  * `+ cadastrarPedido(): void`
  * `+ atualizarAndamento(pedido: Pedido, novoStatus: StatusPedido): void`

### 2.2 Classe `Cliente`
Armazena os dados básicos do cliente anotados no celular.
* **Atributos:**
  * `- idCliente: int`
  * `- nome: String`
  * `- telefone: String`
* **Operações:**
  * `+ cadastrarCliente(): void`
  * `+ consultarCliente(): Cliente`

### 2.3 Classe `Pedido`
Registra a solicitação de serviço e controla seu andamento e valor final.
* **Atributos:**
  * `- idPedido: int`
  * `- dataPedido: Date`
  * `- status: StatusPedido`
  * `- observacoes: String`
  * `- valorTotal: double`
* **Operações:**
  * `+ cadastrar(): boolean`
  * `+ editar(): boolean`
  * `+ atualizarStatus(novoStatus: StatusPedido): void`
  * `+ calcularValorTotal(): double`
  * `+ listarPedidos(): List<Pedido>`
  * `+ listarPendentes(): List<Pedido>`

### 2.4 Classe `ItemCorte`
Detalha a metragem do corte solicitado e aplica o valor unitário praticado (R$ 35,00/m).
* **Atributos:**
  * `- idItem: int`
  * `- descricaoMadeira: String`
  * `- quantidadeMetros: double`
  * `- valorPorMetro: double` (padrão: `35.00`)
* **Operações:**
  * `+ calcularSubtotal(): double`

### 2.5 Enumeração `StatusPedido`
Padroniza o andamento do pedido para facilitar a identificação de pendências.
* **Valores:**
  * `PENDENTE`
  * `EM_CORTE`
  * `CONCLUIDO`
  * `ENTREGUE`

### Relacionamentos entre as classes
* **Responsavel 1 ──── * Pedido:** Um responsável (Eduardo) gerencia vários pedidos.
* **Cliente 1 ──── * Pedido:** Um cliente pode realizar um ou vários pedidos ao longo do tempo.
* **Pedido 1 ◆──── 1..* ItemCorte:** Composição. Um pedido é composto por um ou mais itens de corte; se o pedido for excluído, os itens também são.
* **Pedido ──── StatusPedido:** Associação de dependência para definir o andamento atual do pedido.

## 4. Teste de Mesa com Objetos (Instanciação)

Para validar o diagrama, simulou-se um pedido real baseado na regra de negócio de R$ 35,00 por metro:

* **Objeto `resp1 : Responsavel`**
  * `idResponsavel = 1`
  * `nome = "Eduardo"`
* **Objeto `cli1 : Cliente`**
  * `idCliente = 10`
  * `nome = "Carlos Silva"`
  * `telefone = "(42) 99999-0000"`
* **Objeto `item1 : ItemCorte`**
  * `idItem = 101`
  * `descricaoMadeira = "Viga de Pinus"`
  * `quantidadeMetros = 4.0`
  * `valorPorMetro = 35.00`
  * *Resultado de `calcularSubtotal()`*: `4.0 * 35.00 = 140.00`
* **Objeto `ped1 : Pedido`**
  * `idPedido = 501`
  * `dataPedido = 12/11/2026`
  * `status = PENDENTE`
  * `observacoes = "Cortar no período da manhã"`
  * *Resultado de `calcularValorTotal()`*: `R$ 140,00`

**Conclusão do teste:** O modelo suporta perfeitamente o registro feito pelo celular, calcula o valor exato pela metragem e permite filtrar pedidos com status `PENDENTE`.
