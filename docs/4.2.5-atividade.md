## 1. Do fluxo ao diagrama

| Passo / Fluxo da 4.2.2 | Elemento no diagrama | Raia | Por quê |
|---|---|---|---|
| Início do caso de uso | Início (círculo cheio) | Responsável pelo gerenciamento | O ator inicia o registro do pedido pelo celular. |
| Passo 1: O responsável informa os dados do pedido | Ação: `Informar dados do pedido` | Responsável pelo gerenciamento | Ação executada pelo responsável pelo gerenciamento. |
| Retorno do fluxo alternativo | Junção (losango vazio) | Sistema | Ponto onde o fluxo alternativo retorna antes de o sistema receber os dados novamente. |
| Passo 2: O sistema recebe os dados | Ação: `Receber dados do pedido` | Sistema | O sistema processa as informações enviadas. |
| Passo 3: O sistema verifica se os dados necessários foram preenchidos | Ação: `Verificar dados necessários` + Decisão: `Dados necessários preenchidos?` | Sistema | A verificação vira uma ação com verbo no infinitivo, seguida do losango com a pergunta e saídas `[sim]` e `[não]`. |
| Alternativo (Dados incompletos) — Passo 1 | Ação: `Informar necessidade de completar cadastro` | Sistema | Ocorre na saída `[não]` da primeira decisão para avisar o usuário. |
| Alternativo (Dados incompletos) — Passos 2 e 3 | Ação: `Completar informações` | Responsável pelo gerenciamento | O responsável preenche o que faltou e retorna à junção do fluxo principal. |
| Passo 4: O sistema salva o pedido | Ação: `Salvar pedido` + Decisão: `Pedido salvo com sucesso?` | Sistema | A gravação é uma ação, seguida da decisão que testa se ocorreu falha (`[sim]` ou `[não]`). |
| Exceção (Erro ao cadastrar) — Passos 1, 2 e 3 | Ação: `Informar erro ao realizar cadastro` + Fim 1 | Sistema | Ocorre na saída `[não]` ao salvar; avisa o erro e encerra sem a pós-condição. |
| Passo 5: O sistema informa que o cadastro foi realizado | Ação: `Informar cadastro realizado` | Sistema | Ocorre na saída `[sim]` após salvar com sucesso. |
| Passo 6: O responsável recebe a confirmação | Ação: `Receber confirmação` + Fim 2 | Responsável pelo gerenciamento | O responsável visualiza a confirmação e encerra o fluxo com a pós-condição atingida. |

## 2. Diagrama de atividades

**Figura 3 — Diagrama de atividades do caso de uso UC01 — Cadastrar pedido.**

**Fonte:** Elaborado pelo autor.

### Descrição do desenho
* **Raias:** O diagrama possui duas raias verticais identificadas pelo papel de quem executa: **Responsável pelo gerenciamento** e **Sistema**.
* **Caminho feliz:** Inicia com o responsável informando os dados do pedido, passa para o sistema receber e verificar os campos, salva o pedido, exibe a mensagem de sucesso e termina quando o responsável recebe a confirmação (com a pós-condição).
* **Decisões:** Há duas decisões no sistema. A primeira (`Dados necessários preenchidos?`) desvia na guarda `[não]` para o fluxo alternativo, onde o sistema avisa e o responsável completa os dados voltando pela junção. A segunda (`Pedido salvo com sucesso?`) desvia na guarda `[não]` para o fluxo de exceção de erro ao cadastrar.
* **Fins:** O diagrama possui **2 fins** porque existem dois desfechos distintos: o término com sucesso (com a pós-condição: pedido cadastrado no sistema) e o término por falha técnica ao salvar (sem a pós-condição: erro ao cadastrar).

## 3. Rastreabilidade com a 4.2.2

| Elemento no diagrama (Ação ou saída de decisão) | Origem na 4.2.2 |
|---|---|
| Ação: `Informar dados do pedido` | UC01 — Fluxo principal, Passo 1 |
| Ação: `Receber dados do pedido` | UC01 — Fluxo principal, Passo 2 |
| Ação: `Verificar dados necessários` | UC01 — Fluxo principal, Passo 3 |
| Decisão `Dados necessários preenchidos?` (`[sim]`) | UC01 — Fluxo principal, Passo 3 |
| Decisão `Dados necessários preenchidos?` (`[não]`) → `Informar necessidade de completar cadastro` | UC01 — Fluxo alternativo, Passo 1 |
| Ação: `Completar informações` | UC01 — Fluxo alternativo, Passos 2 e 3 |
| Ação: `Salvar pedido` e Decisão `Pedido salvo com sucesso?` (`[sim]`) | UC01 — Fluxo principal, Passo 4 |
| Decisão `Pedido salvo com sucesso?` (`[não]`) → `Informar erro ao realizar cadastro` | UC01 — Fluxo de exceção, Passos 1 a 3 |
| Ação: `Informar cadastro realizado` | UC01 — Fluxo principal, Passo 5 |
| Ação: `Receber confirmação` | UC01 — Fluxo principal, Passo 6 |

### Conferência
* **Todo passo da especificação virou elemento no diagrama?** Sim. Todos os 6 passos do fluxo principal (totalizando 7 ações), o fluxo alternativo e o fluxo de exceção estão representados dentro do teto esperado.
* **Toda decisão tem duas saídas com guardas (`[sim]` e `[não]`)?** Sim. As duas decisões possuem as duas saídas rotuladas corretamente e contêm apenas perguntas.
* **Há um fim para cada jeito de terminar?** Sim. Há um fim para o término com sucesso e um fim exclusivo para a exceção de erro ao salvar.
* **Nota ❓:** Ao desenhar o diagrama, notou-se que a especificação da 4.2.2 não detalha em qual passo exato o sistema calcula o valor total do pedido (metragem × R$ 35,00), ficando implícito que ocorre antes de salvar o pedido.
